# Methods: The Epistemological Engine

This project is not a traditional literature review. It is the output of an **Epistemological Engine** — an automated, adversarial system designed to subject scientific theories to rigorous Popperian stress-testing.

This page documents the mechanics, models, and protocols used to generate the debates, experiments, and synthesis found on this site.

## 1. The Debate Protocol

Every "Debate" page on this site was generated by an autonomous orchestration script (`scripts/conduct_debate.py`). This script forces two rival theories into a structured, zero-sum contest.

### The Roles
The engine instantiates three distinct AI agents for each debate:

1.  **🔵 The Proponent (Blue Team):**
    *   *Prompt:* "You are the leading proponent of [Theory A]. Your goal is to posit it as the best explanation for aging. Defend it against criticisms using empirical evidence."
    *   *Goal:* Maximize the theory's explanatory power.

2.  **🔴 The Critic (Red Team):**
    *   *Prompt:* "You are a ruthless Popperian critic representing [Theory B]. Your goal is to find logical inconsistencies, lack of falsifiability, and empirical data that contradicts Blue's claims."
    *   *Goal:* Falsify the Proponent's claims.

3.  **⚖️ The Judge (Verdict):**
    *   *Prompt:* "You are a neutral epistemologist. Do not pick a winner based on rhetoric. Identify the *Crucial Experiment* that would empirically settle the dispute."
    *   *Goal:* Synthesis and experimental design.

### The Rounds
1.  **Opening Statement:** Proponent presents strongest evidence and riskiest prediction.
2.  **Critique:** Critic attacks the specific claims made in the opening.
3.  **Defense:** Proponent rebuts the critique.
4.  **Closing:** Judge summarizes the state of the debate and defines the "Crucial Experiment."

## 2. The Models

The intelligence behind the engine is a hybrid system:

*   **Debate Simulation:** The debates were simulated using the **Claude Opus 4.6** model (via the local `claude` CLI default). Claude was chosen for its high verbal reasoning capability and ability to maintain distinct personas without breaking character.
*   **Orchestration & Synthesis:** The **Gemini 3.0** model family (Pro/Flash via CLI Auto routing) acted as the "Meta-Agent." It wrote the python scripts, managed the file system, synthesized the "Grand Synthesis" from the raw debate logs, and built the interactive website features.

## 3. The Interactive Layer ("Living Knowledge")

This site is not static. It features a "Living Knowledge" architecture designed to allow the community to challenge the AI's conclusions.

### The Stack
*   **Frontend:** A custom JavaScript overlay (`chat.js`) that detects text highlighting and opens a context-aware chat sidebar.
*   **Backend:** A local Python server (`local_server.py`) running `FastAPI` that acts as the brain.
*   **Reasoning:** The backend shells out to the local `gemini` CLI to answer questions or evaluate challenges.

### The Self-Correction Loop
1.  **Challenge:** A user challenges a claim in the sidebar.
2.  **Debate:** The AI agent defends the text using the *General Critic* knowledge base.
3.  **Concession:** If the user provides valid counter-evidence, the AI concedes.
4.  **Action:** The AI formats a formal **GitHub Issue** describing the necessary change.
5.  **Automation:** A GitHub Action (`issue_to_pr.yml`) automatically converts approved Issues into **Pull Requests**, directly modifying the site's source code.
